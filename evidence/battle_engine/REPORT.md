# Function-evidence pilot: the battle engine

Branch `evidence-pilot` (from `battle-xcheck` d78bb44). Tools: `tools/evidence/` (README there). The shared files of
the lockstep work (`src/port/xcheck.cpp`, `tools/battle_xcheck.py`, `tools/ares_ref/*`, `src/port/Engine.cpp`,
`patches/game/20-fragment-battle_engine.patch`) are used as they are; nothing in them or in the game sources changed.

Files here: `gb_coverage.md` (what Game Pak parties add), `routes/` (input routes), `frontier.md` (what keeps code unreached: gates, conditions, classes), `proposals.json` /
`gate_trials.md` (automatic memory settings and their trial runs), `dead_code.md`, `coverage.md` (numbers, per file, pointer tables, functions with several runtime callers, runtime edges
the static graph lacks), `records.md` / `records_reviewed.json` (24 reviewed records), `reviews.json` (their
hand-written part). The full per-function file (all 2055 records, 3.5 MB) is regenerated by `analyze.py`.

## What was built

1. **Static call graph** (`callgraph.py`): every battle-engine file compiled with its own flags to -O0 LLVM IR;
   direct calls, address-taken functions, and indirect calls resolved through the pointer tables the function reads.
   Battle engine: 2055 functions (318 `func_`), 8139 call + 381 table + 422 ref edges, 14 pointer tables
   (`gMoveEffectHandlers` 34 handlers, `sBattleSceneStateRowTable` 51, the move-animation start/end tables, the
   particle descriptors). 4 dispatchers call pointers stored at run time (`BattleScene_TickStateCallbacks`,
   `BattleAnim_UpdateParticlePool`, `BattleAnim_UpdateEffectCallbacks`, `BattleAnim_DrawEffectCallbacks`): the
   runtime trace fills those in (194 runtime-only edges). Runs in 5 s; the whole decomp (351 files, 7474 functions,
   553 `func_`, 102 tables) in 16 s.
2. **Instrumented build** (`cmake/evidence.cmake` through `-DCMAKE_PROJECT_INCLUDE`, own directory
   `build-evidence`): the 49 battle-engine sources get `-finstrument-functions -fno-omit-frame-pointer
   -fno-optimize-sibling-calls`; `src/port/evidence/evidence_rt.c` (new) keeps a shadow stack and aggregates per
   (function, instrumented parent, return address) and per call path (10 deep), tagged with the battle context
   (scene phase, attacker side, user species and move, target species, gBattleDamage); a capped call sequence; the
   battle state (both BattleMonRuntime, both ActivePokemonState, BattleScene, gBattleDamage) at entry and exit of
   watched functions. Behaviour-neutral: seed 7 gives the reference battle's 71 events and the same random calls per
   function (117/22/130/6097/21); seeds 1 and 7 match ares event by event with this binary (105 and 71 events).
3. **Scenarios** (`run.py`, `watch.py`): the `battle_xcheck.py` battle with forced values. `watch.py queue` replays a
   baseline's values up to call k and forces one value there; `watch.py ares` runs the same battle in ares with the
   lockstep driver's case rules (`rule Battle_Random@Battle_CheckCriticalHit 34`) and reads its caller-tagged random
   trace; `watch.py diff` prints what each watched call changed. Port-only extra: `--moves` gives the player's
   Pokemon other moves (evidence_rt.c) for effects the rental teams lack.

## Reaching every function: setting the conditions

(Second round.) Reaching all functions means producing, for each one, the state its call path needs. The tools now
find that state and set it:

- **Branch coverage** (`PORT_EVID_COVERAGE`: clang `-fprofile-instr-generate -fcoverage-mapping` on the same files,
  written with the call data) shows every branch side that never ran.
- **`frontier.py`** lists the *gates*: a reached caller whose call to an unreached function sits behind a branch side
  that never ran. For each: the condition's source text (`switch` cases resolved to the switch expression), its class
  (random value, rules constant, battle state, session/save, input, AI, table index), and how many unreached
  functions are behind it (`frontier.md`).
- **Levers**, per class:

| class | lever | where |
|---|---|---|
| random value | forced stream (`watch.py queue`, ares case `rule`) | port + ares |
| table index (which move / effect / animation) | move injection (`run.py --moves`), a sweep of all 165 moves | port (ares needs the case `mon` lines) |
| battle state, flags, constants | memory set at a function's entry (`run.py --set "Fn[#n]:sym*+off:size[\|]=v"`), offsets computed automatically for plain conditions (`frontier.py --build` -> `proposals.json`, tried by `try_gates.py`) | port |
| session / mode / save | the same memory set (`gSessionContext.mode`), or a save file (tools/save_editor) / another route | port; ares with a save |
| Game Boy data (Game Pak Pokémon, Lab, GB Tower, Pokédex, trades) | a generated save (`gb_party.py`) in the Transfer Pak plus a route (`run.py --gb --rec`) | port + ares (with the GB core) |
| input | replays / the autoplay bot (memory writes do not hold: the pad state is refreshed after the entry) | both |
| dead code (no caller, no address in the ROM) | direct call (`run.py --call "At#1:Target:ret:args"`), also gives return values | port |

Results on the battle engine (after the six seeds):

| step | functions reached |
|---|---|
| six seeds | 1020 (49.6%) |
| + the move sweep (165 moves, 42 battles, port-only) | 1691 (82.3%) with the forced runs below |
| + automatic memory proposals: 3 of 8 opened their gate (AI decision flags, a scene cue) | +13 |
| + direct calls of dead code | 1704 (**82.9%**); lines 73.8%, branches 63.2%; `gMoveEffectHandlers` 33/34 |

Forced-condition examples (records updated): the rules mode `D_8438AC60[0]` is initialised to 1 and never written,
so every Game Boy-rules branch is dead in the shipped game; forcing 0 changes the crit formula (turn 1: Machop's
Karate Chop no longer crits with the same roll, 29 damage instead of 55). Counter (injected) doubles the last
Normal/Fighting hit (50 -> 100, 68 -> 136). Rest while poisoned (status and HP forced) reaches
`Battle_ApplyStatStageMultiplier`. Spectator mode (`gSessionContext.mode = 0x10`) reaches the 4 attract/spectator
functions. Direct calls: `BattleAnim_Atan2sFromPoints` confirmed (binary angle of the vector between two points);
`BattleAnim_ApproachS16(&10, 20, 2)` = 30, a scale rather than an approach with its `s16` step.

What is left (351): 154 functions behind 127 gates (66 behind animation-table indices that no single move hits from
this battle's user species, 40 "other state" such as doubles HUD and AI ties, 32 presentation cues, 22 AI, 9 input),
and 197 with no reached caller above them (`dead_code.md`): 9 are referenced only from data (raw addresses in
descriptor tables) and **188 have no reference in the whole decomp's C code and no address word in the ROM**: dead
in the shipped game unless an asm function calls them. For those, a direct call is the only runtime evidence, and
the verdict should say so.

## Game Boy cartridges: modified saves for the paths only Game Pak data reaches

(Third round.) Code that only Game Boy data reaches is reached with a Transfer Pak cartridge and a *generated* save:
the ROM and saves are the user's own dumps and stay out of the repository; what is committed is the recipe
(`tools/evidence/gb_party.py` party strings), the input route and the tools.

- `tools/evidence/gb_party.py <base.sav> <out.sav> "<mon>;..."` writes any party into a Red/Blue/Yellow save:
  species, level, moves (also ones the species cannot learn), DVs, status, HP, PP, nickname, OT name and ID, the
  catch-rate byte; stats, types, growth, internal ids and PP from the decomp's own tables. Base save:
  `tools/gb_save.py --got-pokedex --rom <cart>`.
- `run.py --gb ROM:SAVE --rec ROUTE` (port) and `watch.py ares ... --gb ROM:SAVE --rec ROUTE` (ares) play a battle
  from another route with the cartridge; `routes/free_battle_gamepak.rec` is a Free Battle (1P vs COM, Anything
  Goes) with both teams from the Game Pak, recorded screen by screen (`_slow` has waits long enough for the N64).
- `covdiff.py` lists the functions and source lines a set of runs adds over a baseline (`gb_coverage.md`).

Parties used (recipes, `scenario.json` of each run): (1) Pikachu L25 with OT = the save's player (Yellow partner),
Mew L100 Psychic/Recover/Metronome, Charmander L5 with 4x Hyper Beam; (2) traded and nicknamed Pikachu L50, Mew L100
Metronome/Transform/Mimic/Mirror Move, poisoned Gengar at 20 HP; (3) Ditto, Splash-only Magikarp L100, paralysed
Chansey at 1 HP. Results over the baseline (6 seeds + the 165-move sweep, 48 battles):

- 5 Game Pak battles add **12 functions and 624 source lines** no rental battle reached, e.g. the Yellow partner
  Pikachu's model (`Battle_LoadAnimationAndMarkMoveIllegality` line 415: only when the cart is Yellow, the species
  Pikachu and its OT matches the save's player, `Rental_MarkMatchingPlayerPikachu`) and its voice
  (`Cry_Play(0xC8, ...)`), the TM/HM learnset check behind the illegal-move marks (lines 328-333),
  `BattleScene_PhaseWithdrawFainted`, `BattleAnim_ClearSleepStatusAnimation`, `BattleAI_SelectRandomUsableMoveSlot`.
  The Metronome Mew reaches 1037 functions in one battle (random moves). Caveat: these are Free Battles, the
  baseline is Poké Cup: some AI lines (rule-category cases in `battle_engine_361050.c`) come from the mode.
- **The same battle on the N64:** the lockstep work tree's ares is built with `-DARES_CORES=n64` (no Game Boy core:
  "no Game Boy cartridge slot", so the N64 side silently used a Stadium-box Pokémon). Built here with
  `-DARES_CORES="n64;gb"` (`build-ares-gb/`, this branch's ares_ref.cpp): the cartridge loads and events 0-2 match
  field for field (the GB Pikachu and Mew: stats, moves, HP).
- **A port/N64 difference found with it:** at the computer's first decision the N64 makes one more AI coin flip
  (`BattleAI_RandomBelowInclusive(1)`: a tie-break) than the port; turn 1 is still the same, every later random
  value shifts, and in turn 2 the computer's Mew uses Metronome in the port, Psychic on the N64. In the port the
  equal-speed tie test (`func_8437B0CC`, line 3092) ran 258 times and never saw equal speeds; which of the ten
  tie-break sites flips the coin on the N64 needs the ares function-entry trace (hook request 3). Rental battles
  never showed it (the lockstep seeds matched).

Beyond the battle engine, Game Boy data is read by ~108 functions across ~25 areas (direct callers of the
`GbSave_*` / `GbPak_*` / `osGbpak*` functions: Lab PC 17, GB Tower 13 (+108 tower functions), Pokédex 11, Trade
Machine 9, Lab PC list 7, Transfer Pak select 5, event battles, Pikachu reward, rental viewer ...). Their conditions
are save contents: the next save mutations to generate are box contents (full / empty boxes), the Pokédex flags
(151 owned), event flags (Pokédex obtained), the map (saved outside a Pokémon Center: the Lab's refusal), bad
checksums (corrupt-save paths), the game (Red/Blue/Yellow: `GbSave_GetPortGame`), two cartridges (Trade Machine:
`PORT_GB_ROM2`). Same tools: a mutation in `gb_party.py`'s style, a route, `covdiff.py`.

## Records (26)

Verdicts: confirmed 18, unclear 7 (5 unnamed functions whose behaviour is now established, with a proposed name;
one PORT-changed function; `BattleAnim_ApproachS16`), name wrong 1. (First round: 24 records with one "not reached",
`Battle_ApplyStatStageMultiplier`, reached in the second round by forcing Rest while statused.) Highlights:

- `Battle_CheckCriticalHit` confirmed, and a **field-name bug** found with it: the crit threshold is computed from
  `gBaseStats[id].baseDefense`, which is the species' base **Speed** (gBaseStats = gSpeciesData - 0x1C; the
  `PokemonStats` stat names in `gb_data.h` are in reverse order). Forced crit roll 34 crits and 35 does not, in the
  port and in ares; 35 is exactly the Speed formula ((65 + 76) >> 2), Defense would give 29.
- `func_843708CC` (accuracy check): forcing 254 and 255 on a 100% move shows the redraw of 255 — Stadium removed the
  Game Boy's 1/256 miss (same in ares). Proposed `Battle_CheckMoveHit`; `func_843708A0` = `Battle_SetMoveMissed`,
  `func_84372670` = `Battle_ExecuteMove`, `func_84370B44` = `Battle_ApplyBurnAttackPenalty` (forced burn: Attack
  98 -> 49, same in ares), `func_84370ADC` = `Battle_SyncStatusToParty` (by code; its effect is outside the dump).
- `Battle_Effect_Counter` **name wrong**: not a table effect but a gate run before every move's damage (83 calls,
  every move); returns 1 unless the move is Counter. Proposed `Battle_TryCounter`.
- Effect handlers with state diffs: SecondaryStatusChance (forced burn), Confuse (unk_4C 0x80, 2-5 turns in unk_50),
  Sleep (a miss, then status 3), Heal (Recover +max/2), RaiseOwnStat (Swords Dance stage 7 -> 9, Attack x2), Haze,
  FocusEnergy (unk_4D bit 2, read by the crit check), Substitute (max/4 HP into unk_59). These also name 6 fields.
- Forced situations used: a crit (7 values bracketing the threshold), a miss roll on a 100% move and the 255
  redraw, a secondary burn; with injected moves a status move missing (Hypnosis) and a natural Fire Blast miss. Not
  forced yet: a status move failing on an already statused target, Recover failing at full HP.

## Effort per function

- Automatic (static paths, runtime callers and paths, context, counts): seconds for all 2055 functions; a full
  battle is ~50 s in the port, ~80 s in ares, two at a time.
- A forced scenario: 5-15 min to find the call to force (from the caller-tagged ares trace or the sequence log),
  then 15-50 s per run per side. One scenario usually serves 2-4 records (the crit runs gave 3).
- Review and writing: 3-6 min per record with the state diff at hand; ~10-20 min when a field layout had to be
  worked out (gBaseStats). The 24 records took about 2 hours including the scenarios.

## What blocked functions from being reached

1. **One battle setup.** `battle_xcheck.py`'s route always plays Poke Cup round 1 with the same rentals: the
   move-specific effect handlers (16 of 34) and most move-animation code need other moves. The port-only move
   injection reached 6 more handlers, but its evidence has no ares counterpart.
2. **Rule variants and modes not played:** the Game Boy-rules branches (`D_8438AC60[0] != 1`), attract mode
   (`BattleScene_TickAttractModeInput`), two-player input, Rest while statused (`Battle_ApplyStatStageMultiplier`),
   Counter itself, Metronome/Mirror Move, faint-replacement corners.
3. **State outside the dump:** static flags (`sBattleMoveFailed`, `sBattleCritFlag`), the party entries
   (TeamRoster), return values (`-finstrument-functions` gives none).
4. **PORT-changed functions** (32, 27 reached): where the port's hook decides (`BattleScene_IsActionSelectionTimerExpired`
   under PORT_XCHECK_COM), the run says nothing about the original logic.
5. **The autoplay bot** is not usable with this binary: its port side (`src/port/bot.cpp`) is on the `autoplay`
   branch, not in d78bb44. Merging `autoplay` into this branch would allow castle/leader battles with other teams.
6. Inlining: for inlined functions the return address names the caller's caller; the shadow stack gives the right
   parent (the records use it), so only entries from main code rely on the return address.

## Hook changes needed from the lockstep side

The ares binary used here is a copy of the lockstep work tree's current build (its `rule`/`mon` case file and
`ARES_REF_XCHECK_SYMS` caller names are not in d78bb44); records name the binary's sha256 prefix 939fff132f8cbc77.

1. Commit the case format on both sides (`PORT_XCHECK_CASE` / `ARES_REF_XCHECK_CASE`), and add a **one-shot rule**
   (by call index, not cycling), e.g. `rule Battle_Random@Battle_Effect_SecondaryStatusChance#0 0`: today ares's
   rule forces every call from that caller while the port queue forces one, so forced runs stay comparable only
   up to the next call from the same caller (the burn run diverges at the second Flamethrower).
2. The `mon` lines (moves, species, status, HP) on both sides: they replace the port-only `PORT_EVID_MOVES` and make
   every effect handler ares-checkable.
3. **An ares function-entry trace** for the battle engine: the driver has the symbol file and the host-hook list;
   one hook per function start logging (function, caller from RA) counts and paths would give the N64's own call
   graph and coverage to compare with the port's — the only independent check for the 32 PORT-changed functions.
4. Build ares_ref with the Game Boy core (`-DARES_CORES="n64;gb"` in tools/ares_ref/build.sh): without it the
   N64 side runs without the cartridge and nothing says so but one log line. Then: return values (v0 at the hooked return address) for a watch list, and the statics `sBattleMoveFailed`,
   `sBattleCritFlag` plus the TeamRoster party entries in the event dump.
5. The planned ares save state at the order screen (faster scenario runs).
6. (Second round) The same forced-condition levers in ares, so forced runs are N64 evidence too: a memory write at a
   hooked function's entry (the `--set` paths: symbol, pointer loads, offsets; the driver already writes RDRAM
   through the data cache for the `mon` lines), and a direct call of a function from a hook (set the argument
   registers, a return address back into the hook, jump), for the 188 functions nothing calls.

## Scaling to the whole decomp (~7,400 functions, 541 `func_`, 33 asm)

1. **Static graph for everything now** (done in 16 s: 7474 functions, 102 tables, 389 functions with
   pointers stored at run time). Group functions into subsystems by file and graph component.
2. **Reach plan per subsystem**, the battle-engine loop: run the natural drivers, `frontier.py` for the gates,
   then the lever for each class (forced random, injected moves/parties, automatic memory proposals tried by
   `try_gates.py`, saves for session/mode gates, input scripts), repeat until only gates without a lever remain,
   then direct calls for code with no reference anywhere (the dead-code check: no C reference in the whole decomp
   graph and no address word in the ROM). Every record names how its function was reached: natural, forced random,
   injected, memory-forced, or direct call, so the strength of each piece of evidence stays visible.
3. **Instrument by subsystem**, not all at once: `PORT_EVID_FILES` per fragment (the per-frame graphics code would
   dominate the counts otherwise). Use the same runtime; add SanitizerCoverage (`trace-pc-guard`) builds for cheap
   whole-game coverage and keep `-finstrument-functions` for the paths of the subsystem under review.
4. **Drivers per area:** battles with the lockstep cases (all moves, all rule sets, castle and cups through the
   autoplay bot once merged), menus and minigames with the recorded replays (`replays/*.rec`, `tools/tour.py`),
   GB Tower with its saves. Each driver run is reproducible (forced random, recorded input).
5. **Automatic triage** into: not reached (needs a driver), reached through one path matching the static graph
   (cheap review), several callers (check the name fits every use), runtime-only edges (dispatch to document),
   PORT-changed (ares needed). Review order: the 541 `func_` that are reached, then names whose state diff
   contradicts them (diff heuristics: which fields change), then the rest.
6. **Ares parity** for every subsystem through the function-entry trace (hook request 3), with fragment relocation
   handled as for fragment 51 (`gFragments[n]`).
7. The 33 asm functions have no C body in the port to instrument: cover them through their C callers on the port
   side and the ares entry trace.
8. Estimated effort: the automatic part is a few hours of machine time per subsystem; reviews at 3-6 min each are
   ~400-700 hours for everything by hand, so batch by scenario (one forced situation confirms several functions)
   and review the reached `func_` and the multi-caller functions first (~1,500 functions, ~100-150 hours).

## Reproducing

```

nice -n 15 cmake --build build-evidence -j 4
tools/evidence/callgraph.py build-evidence /tmp/cg.json
tools/evidence/run.py /tmp/s7 --bin build-evidence/pokestadium --seed 7 --frames 30000
tools/evidence/watch.py queue /tmp/s7 /tmp/crit34.txt Battle_Random 0 34
tools/evidence/run.py /tmp/crit34 --bin build-evidence/pokestadium --seed 7 --queue /tmp/crit34.txt --frames 3800 \
    --watch Battle_CheckCriticalHit,Battle_ApplyDamageRandomFactor
tools/evidence/analyze.py /tmp/cg.json evidence/battle_engine /tmp/s7 /tmp/crit34 --reviews evidence/battle_engine/reviews.json
```
